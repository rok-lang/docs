# E0105: value used after it was handed over

The value was moved into a lock, sent through a channel, handed to a task (as `task::spawn_blocking_with_arg`'s argument, or as a spawned future), or moved into a closure with `[move x]`, and is used again here; its new owner may be changing it. Pass `.clone()` to keep a separate copy, or give the variable a new value first.

```rok norun
let xs = [1, 2, 3];
let m = Mutex::new(xs);
xs.push(4);
```

```text check=checks/E0105.rok
error[E0105]: `xs` was moved into the `Mutex` at line 2
  --> main.rok:3:1
   |
 2 | let m = Mutex::new(xs);
   |         -------------- `xs` moved into the `Mutex` here
 3 | xs.push(4);
   | ^^
   |
   = help: it belongs to the `Mutex` now; use it through the lock: `using g = m.lock() { g.get().push(4) }`, or hand over `xs.clone()` to keep a separate copy
```

Use the value through the lock, or hand over `xs.clone()` if you need your own copy:

```rok
let xs = [1, 2, 3];
let m = Mutex::new(xs);
using g = m.lock() { g.get().push(4) }
using g = m.lock() { println(f"{g.get().len()}") }
```

```output
4
```

Rok has no move semantics, so `xs` still refers to the same object; using it afterwards would race with the new owner. The check follows copies, fields, collection elements, closure captures and calls. [Chapter 12](../learn/12-concurrency.html) shows more cases.
