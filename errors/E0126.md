# E0126: link failed

The program type-checked, but the link failed: the system linker reported an error, or could not find a native library. `rokc check` stops before linking, so a link failure shows up only when building (`rok build`, `rok run`, `rokc build`). The usual cause is a function declared in an `extern` block whose library is not linked: libc and libm are linked by default, anything else needs `#[link]` ([6.2.3](../spec/refs-lang/006-meta-system/602-built-in-attributes.html#623-link-naming-an-external-library)). Check the `-L` directories and `#[link]` names, and that the system linker is installed.

This program calls a zlib function without linking zlib:

```rok norun
extern "C" {
    fn compressBound(len: u64) -> u64;
}

println(f"{unsafe { compressBound(1000) }}");
```

On macOS, `rokc build` prints (shortened; the linker's text differs between platforms):

```text
   Compiling main (.)
error[E0126]: the link failed:
ld64.lld: error: undefined symbol: _compressBound
>>> referenced by main.rok:5 (.../main.rok:5)
...
```

`compressBound` is in zlib. Link it:

```rok
#[link("z")]
extern "C" {
    fn compressBound(len: u64) -> u64;
}

println(f"{unsafe { compressBound(1000) }}");
```

```output
1013
```
