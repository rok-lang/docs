# E0142: method generic parameter named like its impl's

A method written in an `impl` block declares a generic parameter with the name of one of the impl's. Inside the method the name could mean either, so it is an error.

```rok norun
struct Wrap<K> { k: K; }

impl<K> Wrap<K> {
    fn pick<K>(self, x: K) -> K { x }
}
```

```text check=checks/E0142.rok
error[E0142]: generic parameter `K` of `pick` is already a parameter of its `impl`
  --> main.rok:4:5
   |
 4 |     fn pick<K>(self, x: K) -> K { x }
   |     ^^
   |
   = help: rename the method's (`fn pick<K2>`), or drop it to use the impl's `K`
```

Give the method's parameter its own name:

```rok
struct Wrap<K> { k: K; }

impl<K> Wrap<K> {
    fn pick<U>(self, x: U) -> U { x }
}

println(Wrap { k: "s" }.pick(5));
```

```output
5
```

A trait's default method is written in the trait, not in the impl, so its parameters shadow an implementing impl's of the same name without an error ([2.10.1](../spec/refs-lang/002-types/210-generics.html#2101-where-parameters-are-declared)).
