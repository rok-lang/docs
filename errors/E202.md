# E202: use after hand-off

A value was used after it was handed over to another owner. `Mutex::new(xs)`, `RwLock::new(xs)`, `tx.send(xs)` and `task::spawn` give `xs` to something other threads can reach. Rok has no move semantics, so `xs` still refers to the same object; using it afterwards would race with the new owner. The check follows copies, fields, collection elements, closure captures and calls ([stdlib 2.13.9](../spec/refs-standard-libraries/200-core/213-marker.html#2139-send--sync---thread-boundary-markers)).

```rok norun
let xs = [1, 2, 3];
let m = Mutex::new(xs);
xs.push(4);
```

```text check=checks/E202.rok
error[E202]: `xs` was moved into the `Mutex` at line 2
  --> main.rok:3:1
   |
 2 | let m = Mutex::new(xs);
   |         -------------- `xs` moved into the `Mutex` here
 3 | xs.push(4);
   | ^^
   |
   = help: it belongs to the `Mutex` now; use it through the lock: `using g = m.lock() { g.get().push(4) }`, or hand over `xs.clone()` to keep a separate copy
```

Use the value through the lock, or hand over `xs.clone()` if you need your own copy:

```rok
let xs = [1, 2, 3];
let m = Mutex::new(xs);
using g = m.lock() { g.get().push(4) }
using g = m.lock() { println(f"{g.get().len()}") }
```

```output
4
```
