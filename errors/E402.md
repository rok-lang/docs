# E402: link or external tool error

The program type-checked, but a later step outside the front end failed: the LLVM back end, or the system linker. `rokc check` stops before linking, so a link failure shows up only when building (`rok build`, `rok run`, `rokc build`). The usual cause is a function declared in an `extern` block whose library is not linked: libc and libm are linked by default, anything else needs `#[link]` ([6.2.3](../spec/refs-lang/006-meta-system/602-built-in-attributes.html#623-link-naming-an-external-library)).

```rok norun
extern "C" {
    fn compressBound(len: u64) -> u64;
}

println(f"{unsafe { compressBound(1000) }}");
```

On macOS, `rokc build` prints (shortened; the linker's text differs between platforms):

```text
   Compiling main (.)
    Building ./target/debug/main
error[E402]: the link failed:
...
ld64.lld: error: undefined symbol: _compressBound
>>> referenced by main.rok:5 (.../main.rok:5)
...
```

`compressBound` is in zlib. Link it:

```rok
#[link("z")]
extern "C" {
    fn compressBound(len: u64) -> u64;
}

println(f"{unsafe { compressBound(1000) }}");
```

```output
1013
```

A failure inside the LLVM back end reports `error[E402]: LLVM back end failed:` followed by its output.
