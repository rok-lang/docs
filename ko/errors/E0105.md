# E0105: 넘긴 뒤에 쓴 값

값을 락에 넣었거나, 채널로 보냈거나, task에 넘겼거나(`task::spawn_blocking_with_arg`의 인자로, 또는 spawn한 future로), `[move x]`로 클로저에 옮긴 뒤 여기서 다시 씁니다. 새 소유자가 그 값을 바꾸고 있을 수 있습니다. 따로 복사본을 두려면 `.clone()`을 넘기거나, 변수에 먼저 새 값을 주세요.

```rok norun
let xs = [1, 2, 3];
let m = Mutex::new(xs);
xs.push(4);
```

```text check=checks/E0105.rok
error[E0105]: `xs` was moved into the `Mutex` at line 2
  --> main.rok:3:1
   |
 2 | let m = Mutex::new(xs);
   |         -------------- `xs` moved into the `Mutex` here
 3 | xs.push(4);
   | ^^
   |
   = help: it belongs to the `Mutex` now; use it through the lock: `using g = m.lock() { g.get().push(4) }`, or hand over `xs.clone()` to keep a separate copy
```

락을 거쳐 값을 쓰거나, 따로 복사본이 필요하면 `xs.clone()`을 넘기세요.

```rok
let xs = [1, 2, 3];
let m = Mutex::new(xs);
using g = m.lock() { g.get().push(4) }
using g = m.lock() { println(f"{g.get().len()}") }
```

```output
4
```

Rok에는 move 의미론이 없으므로 `xs`는 여전히 같은 객체를 가리킵니다. 넘긴 뒤에 쓰면 새 소유자와 경쟁 상태가 생깁니다. 이 검사는 복사, 필드, 컬렉션 원소, 클로저 캡처, 호출을 따라갑니다. [12장](../learn/12-concurrency.html)에 경우가 더 있습니다.
