# E402: 링크 또는 외부 도구 에러

프로그램은 타입 검사를 통과했지만 프런트엔드 다음 단계인 LLVM 백엔드나 시스템 링커가 실패했습니다. `rokc check`는 링크 전에 멈추므로 링크 실패는 빌드할 때(`rok build`, `rok run`, `rokc build`)에만 드러납니다. 흔한 원인은 `extern` 블록에 선언한 함수의 라이브러리를 링크하지 않은 것입니다. libc와 libm은 기본으로 링크하고 그 밖의 라이브러리에는 `#[link]`가 필요합니다([6.2.3](../spec/refs-lang/006-meta-system/602-built-in-attributes.html#623-link-외부-라이브러리-명시)).

```rok norun
extern "C" {
    fn compressBound(len: u64) -> u64;
}

println(f"{unsafe { compressBound(1000) }}");
```

macOS에서 `rokc build`는 다음을 출력합니다(줄였습니다. 링커의 문구는 플랫폼마다 다릅니다).

```text
   Compiling main (.)
error[E402]: the link failed:
ld64.lld: error: undefined symbol: _compressBound
>>> referenced by main.rok:5 (.../main.rok:5)
...
```

`compressBound`는 zlib에 있습니다. zlib을 링크하세요.

```rok
#[link("z")]
extern "C" {
    fn compressBound(len: u64) -> u64;
}

println(f"{unsafe { compressBound(1000) }}");
```

```output
1013
```

LLVM 백엔드 안에서 실패하면 `error[E402]: LLVM back end failed:` 뒤에 백엔드의 출력을 붙여 보고합니다.
