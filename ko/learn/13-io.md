# 13. 파일과 네트워크 IO

이 장에서는 프로그램이 바깥 세계와 주고받는 방법을 다룹니다. 파일과 디렉터리, 경로, 표준 IO, 환경 변수, 자식 프로세스, TCP / UDP 소켓은 모두 `rok::std`에 있습니다.

IO는 언제든 실패할 수 있으므로 거의 모든 함수가 `throws (IoError)`입니다. 이 장 내내 [10장](10-errors.html)의 `try` / `catch`를 씁니다.

## 파일 읽고 쓰기

가장 간단한 방법은 `fs::write`와 `fs::read_to_str`입니다. 이 함수는 파일을 대신 열고 닫습니다. 예제는 `env::temp_dir()` 아래에 디렉터리를 만들어 그 안에서 작업하고 마지막에 지웁니다.

```rok
use rok::std::fs;
use rok::std::env;
use rok::std::process;
use rok::core::io::IoError;

fn main() throws (IoError) {
    let dir = env::temp_dir() / f"rok_learn13_{process::id()}";
    try fs::create_dir_all(dir / "notes" / "2026");

    try fs::write(dir / "hello.txt", "first line\nsecond line\n");
    let text = try fs::read_to_str(dir / "hello.txt");
    print(text);
    println(f"{text.lines().count()} lines");

    try fs::read_to_str(dir / "nope.txt") catch e {
        println(f"error kind: {e.kind():?}");
        ""
    };

    try fs::remove_dir_all(dir);
    println(f"exists after cleanup: {fs::exists(dir)}");
}
```

```output
first line
second line
2 lines
error kind: NotFound
exists after cleanup: false
```

`IoError`에는 `kind()`(`NotFound`, `PermissionDenied`, `TimedOut`, 다른 프로세스가 파일이나 장치를 쥐고 있을 때의 `ResourceBusy` 등)와 사람이 읽을 수 있는 메시지가 있습니다. 에러 종류에 따라 분기하려면 `kind()`를 비교합니다.

경로 인자로는 `str` 값과 `Path`(`AsPath` 트레잇)를 모두 받으므로 `"a.txt"`와 `dir / "a.txt"`를 똑같이 넘길 수 있습니다.

## `File`과 여는 함수

조금씩 쓰거나 한 줄씩 읽으려면 `File`을 직접 엽니다. `using` 블록을 쓰면 블록을 빠져나갈 때 파일이 닫히고, 문장 `using f = ..;`는 아래 `show`처럼 감싸는 블록이 끝날 때 닫습니다. 파일 닫기는 실패할 수 있으므로 컴파일러가 대신 닫지 않습니다. `using`으로 묶거나 `try f.close()`를 부르세요. 열린 채로 남은 `File`은 컴파일 에러입니다. 여는 방식마다 함수가 따로 있어서 잘못된 조합은 쓸 수 없습니다. `File::open`(있는 파일, `WriteOnly` 같은 `Access`를 넘기지 않으면 읽기 전용), `File::create`(만들거나 비움), `File::create_new`(파일이 있으면 실패), `File::open_or_create`, `File::append`(없으면 만들고, 쓰기는 늘 끝에)입니다.

```rok
use rok::std::fs;
use rok::std::fs::File;
use rok::std::env;
use rok::std::process;
use rok::std::path::Path;
use rok::core::io::{IoError, BufReader};

fn show(log: Path) throws (IoError) {
    using r = BufReader::new(try File::open(log));
    try for line in r.lines() {
        println(f"> {line}");
    }
}

fn main() throws (IoError) {
    let log = env::temp_dir() / f"rok_learn13_log_{process::id()}.txt";

    using f = try File::create(log) {
        try f.write_all("start\n");
    }
    using f = try File::append(log) {
        try f.write_all("more\n");
    }
    try show(log);
    try fs::remove_file(log);
}
```

```output
> start
> more
```

`File::create`는 파일을 만들거나 비우고, `File::open`은 읽기 전용으로 엽니다. 읽기와 쓰기는 `io::Read`와 `io::Write` 트레잇의 메서드이고, 모든 파일이 `use` 없이 씁니다. 줄 단위로 읽으려면 버퍼가 필요하므로 파일을 `io::BufReader`로 감쌉니다. reader를 닫으면 파일도 닫힙니다. 이름을 그대로 쓰려면 다시 선언합니다. `let f = BufReader::new(f);`는 파일을 reader로 옮기므로 reader만 닫으면 됩니다. `lines()`는 줄바꿈을 뺀 한 줄씩을 주고, 읽기 에러는 던져서 루프를 끝내므로 `try for`로 씁니다.

`r.lines()`는 `r`의 뷰입니다. reader를 거쳐 읽고, `r`을 가진 쪽의 범위 안에 머뭅니다. 함수에서 돌려주거나, 그 범위 뒤까지 들고 있거나, task에 캡처하면 컴파일 에러([E0140](../errors/E0140.html))가 나고, 에러가 고칠 방법을 알려 줍니다.

```text check=checks/E0140.rok
error[E0140]: this returns a view of `r` out of `r`'s scope
  --> main.rok:6:9
   |
 6 |         return r.lines();
   |         ^^^^^^
   |                --------- a view of `r` made here
   |
   = help: `r.lines()` reads through `r` and stays in its scope; use it there (`try r.lines().collect()`), or take the owning form `r.into_lines()`, which owns `r` and closes it with itself
```

`r`을 옮겨도 뷰는 같은 식으로 끝납니다. `let kept = r;`, `r`을 값으로 받는 호출, `[move r]`, 구조체에 `r` 담기 뒤에는 그 전에 만든 뷰를 쓸 수 없습니다. 뷰를 먼저 다 쓰거나, 소유하는 형태를 대신 옮기세요.

호출 하나가 빌리기만 하려고 만든 reader나 파일은 호출이 끝나면 가진 쪽이 없어 아무도 닫지 않습니다. `(try File::open(p)).read_to_str()`나 `BufReader::new(try File::open(p)).lines()`가 그렇고, 이것은 [E0135](../errors/E0135.html)입니다. 먼저 `using f = try File::open(p);`로 묶은 뒤 `try f.read_to_str()`를 부르세요.

줄들이 범위를 벗어나야 하면 소유하는 형태인 `r.into_lines()`를 씁니다. 이것은 `io::Owned`를 돌려주는데, reader를 가져가고, 줄들을 닫을 때(`try ls.close()`) reader도 닫고, `into_inner()`로 돌려주며, 함수에서 돌려주거나 task로 옮길 수 있습니다(reader가 `Send`이면 이것도 `Send`입니다).

```rok
use rok::std::fs;
use rok::std::fs::File;
use rok::std::env;
use rok::std::process;
use rok::core::io::{IoError, BufReader, Lines, Owned};

// The lines own the reader, so they can leave the function.
fn open_lines(path: str) throws (IoError) -> Owned<Lines<BufReader<File>>, BufReader<File>> {
    BufReader::new(try File::open(path)).into_lines()
}

fn main() throws (IoError) {
    let log = env::temp_dir() / f"rok_learn13_owned_{process::id()}.txt";
    try fs::write(log, "start\nmore\n");

    let ls = try open_lines(log.as_str());
    try for line in ls {
        println(f"> {line}");
    }
    try ls.close();                  // closes the reader and the file
    try fs::remove_file(log);
}
```

```output
> start
> more
```

`bytes` / `into_bytes`, `split` / `into_split`, `take` / `into_take`, async의 `lines_async` / `into_lines_async`와 `bytes_async` / `into_bytes_async`, listener의 `incoming` / `into_incoming`도 같은 짝입니다. `a.chain(b)`는 언제나 두 reader를 소유하고 둘 다 닫으며, `into_inner()`로 두 reader를 돌려줍니다. `take` 뷰에는 `into_inner()`가 없습니다. 나중에 reader를 돌려받으려면 `into_take`와 그 `into_inner()`를 쓰세요.

## 디렉터리와 `Dir` capability

`fs::walk`는 디렉터리를 이름 순서대로 깊이 우선으로 순회합니다. `fs::read_dir` 함수는 한 단계만 나열합니다. 디렉터리 읽기는 어느 항목에서든 실패할 수 있으므로 둘 다 `try for`로 돕니다.

`Dir` 타입은 조금 특별합니다. `Dir` 핸들은 **capability**입니다. `Dir::root()`는 일반 경로로 동작하는 기본 핸들입니다. 거기서 `open_dir`로 연 `Dir` 핸들은 그 디렉터리 안에만 닿을 수 있습니다. 절대 경로나 `..`로 빠져나가려 하면 거부됩니다. 사용자 입력이나 아카이브 안의 이름처럼 신뢰할 수 없는 경로를 다룰 때 안전망이 됩니다.

```rok
use rok::std::fs;
use rok::std::fs::Dir;
use rok::std::env;
use rok::std::process;
use rok::core::io::IoError;

fn main() throws (IoError) {
    let base = env::temp_dir() / f"rok_learn13_dir_{process::id()}";
    try fs::create_dir_all(base / "notes" / "2026");
    try fs::write(base / "notes" / "a.md", "# a");
    try fs::write(base / "notes" / "2026" / "b.md", "# b");

    try for e in fs::walk(base) {
        let rel = e.path().strip_prefix(base) ?? e.path();
        if rel.as_str() != "" { println(f"{rel} dir={e.is_dir()}"); }
    }

    using d = try Dir::root().open_dir(base / "notes") {
        println(f"inside: {d.exists("a.md")}");
        try d.open("../../escape.txt").close() catch e { println(f"refused: {e.kind():?}"); };
        try d.open("/etc/hosts").close() catch e { println(f"refused: {e.kind():?}"); };
    }

    try fs::remove_dir_all(base);
}
```

```output
notes dir=true
notes/2026 dir=true
notes/2026/b.md dir=false
notes/a.md dir=false
inside: true
refused: PermissionDenied
refused: PermissionDenied
```

`create_dir`, `remove_file`, `remove_dir`, `rename`, `copy`, `metadata`도 자유 함수와 `Dir` 메서드 양쪽으로 쓸 수 있습니다.

## 경로: `Path`

`rok::std::path::Path`는 UTF-8 경로입니다. Python의 `pathlib`처럼 `/` 연산자로 경로를 잇습니다. 경로에는 부모나 확장자가 없을 수도 있으므로 그런 메서드는 `T | none`을 반환합니다.

```rok
use rok::std::path::Path;

let p = Path::new("/home/rok/src/main.rok");
println(f"parent:    {p.parent() ?? Path::empty()}");
println(f"file name: {p.file_name() ?? "-"}");
println(f"stem:      {p.file_stem() ?? "-"}");
println(f"extension: {p.extension() ?? "-"}");
println(f"absolute:  {p.is_absolute()}");

let q = Path::new("docs") / "guide" / "intro.md";
println(f"joined:    {q}");
println(f"swapped:   {q.with_extension("html")}");
println(f"normal:    {Path::new("a/./b/../c").normalize()}");
for c in q.components() { print(f"[{c.as_str()}]"); }
println("");
```

```output
parent:    /home/rok/src
file name: main.rok
stem:      main
extension: rok
absolute:  true
joined:    docs/guide/intro.md
swapped:   docs/guide/intro.html
normal:    a/c
[docs][guide][intro.md]
```

`normalize`는 문자열만 정리합니다. `canonicalize`는 파일 시스템에 물어보고 심볼릭 링크까지 풉니다.

## 표준 IO와 환경

`print`는 줄바꿈 없이 쓰고, `eprint` / `eprintln`은 표준 에러에 씁니다. 버퍼링하거나 명시적으로 출력하려면 `io::stdout()` / `io::stderr()`를 씁니다. `io::read_line()`은 줄바꿈을 뺀 다음 줄을 반환하고, 입력이 끝나면 `none`을 반환합니다. 모든 줄을 읽으려면 `try for line in io::stdin().lines()`로 씁니다. `io` 모듈과 `Read` / `Write` 트레잇은 `use` 없이 씁니다.

```rok build
use rok::core::io::IoError;

fn main() throws (IoError) {
    let out = io::stdout();
    try out.write_all("Your name? ");
    try out.flush();
    match try io::read_line() {
        line: str => println(f"Hello, {line.trim()}!"),
        none => println("(no input)"),
    }
    try io::stderr().write_all("bye\n");
}
```

명령줄 인자와 환경 변수는 `rok::std::env`에 있습니다. `env::args()`의 0번 원소는 실행 파일 경로입니다. `env::var`는 변수가 설정되어 있지 않으면 `VarError`를 던집니다.

```rok
use rok::std::env;

let args = env::args();
println(f"{args.len()} arg(s)");

unsafe { try! env::set_var("ROK_GREETING", "annyeong"); }
println(try env::var("ROK_GREETING") catch _ { "unset" });
unsafe { try! env::remove_var("ROK_GREETING"); }
println(try env::var("ROK_GREETING") catch e { f"error: {e}" });

let mine = env::vars().filter(|kv| kv.0.starts_with("ROK_GREETING")).count();
println(f"matching vars: {mine}");
println(f"temp is absolute: {env::temp_dir().is_absolute()}");
```

```output
1 arg(s)
annyeong
error: environment variable not found
matching vars: 0
temp is absolute: true
```

`set_var`와 `remove_var`는 `unsafe`이고 오류를 던집니다. Rok의 `env` 함수끼리는 락을 함께 쓰지만, C 코드가 같은 순간에 환경을 읽는 것은 막을 수 없습니다. 그러니 환경은 스레드를 만들기 전에 바꾸세요. 이름이 비었거나 `=`나 NUL을 담으면 `IoError`(`InvalidInput`)를 던집니다. 자식 프로세스 하나에만 변수를 정하려면 `unsafe`가 필요 없는 `Command::env`를 쓰세요.

## 자식 프로세스

`process::Command`는 다른 프로그램을 실행합니다. 인자, 환경, 작업 디렉터리를 빌더 메서드로 정한 뒤 세 메서드 중 하나로 실행합니다. `output()`은 종료를 기다려 stdout / stderr를 모으고, `status()`는 종료 상태만 돌려주고, `spawn()`은 기다리지 않고 `Child`를 반환합니다.

```rok
use rok::std::process::Command;
use rok::core::io::IoError;

fn main() throws (IoError) {
    let out = try Command::new("echo").args(["hello", "from", "echo"]).output();
    print(try str::from_utf8(out.stdout) catch _ { "" });
    println(f"success: {out.status.success()}");

    let st = try Command::new("sh").args(["-c", "exit 3"]).status();
    println(f"code: {st.code() ?? -1}");

    try Command::new("no-such-program").status() catch e {
        println(f"spawn failed: {e.kind():?}");
    };
}
```

```output
hello from echo
success: true
code: 3
spawn failed: NotFound
```

`out.stdout`은 바이트(`List<u8>`)이므로 `str::from_utf8`로 텍스트로 바꿉니다. 시그널로 죽은 프로세스의 `code()`는 `none`이고, Linux와 macOS에서는 `st.signal()`이 그 시그널을 알려 줍니다(`Signal::Kill`, ..). 빌더 메서드는 바뀐 복사본을 돌려주고 호출한 쪽 명령은 그대로 두므로, `let base = Command::new("git"); let log = base.arg("log");` 뒤에도 `base`에는 `log`가 없습니다.

자식의 스트림은 `Stdio`가 정한 곳으로 갑니다. `Stdio::Piped`이면 `take_stdin()`, `take_stdout()`, `take_stderr()`로 `Child`에서 파이프를 꺼냅니다(파이프로 연결하지 않았거나 이미 꺼냈다면 `none`). 꺼낸 쪽이 주인이 되어 직접 닫습니다. `Stdio::File(f)`로 옮긴 `File`은 명령의 것이 됩니다. 명령을 실행하면 여러분 쪽 사본을 닫으므로 옮긴 뒤에는 `f`를 쓸 수 없고, 자식은 자기 사본을 따로 가집니다. `Stdio::File`을 가진 명령은 한 번만 실행됩니다. 다시 실행하려면 새 파일(`f.try_clone()`)을 주세요. `Stdio::File` 값도 소유자가 하나입니다. 두 명령에 주거나 한 명령의 두 스트림에 주면(`.stdout(s).stderr(s)`) 에러이므로([E0134](../errors/E0134.html)) 각자 `Stdio::File(try f.try_clone())`을 주세요. `Stdio::Inherit`, `Null`, `Piped`는 아무것도 가지지 않으므로 다시 써도 됩니다. 명령에 주지 않은 `Stdio::File`은 그 `File`처럼 직접 닫아야 합니다(`try s.close()`).

`Child`의 주인은 하나이고, 그 주인이 자식을 기다립니다. 주인이 기다리는 동안 다른 곳에서 자식을 멈추려면(타임아웃, 종료) `child.handle()`을 씁니다. 다른 스레드나 task는 이 `ChildHandle`로 자식에게 `kill()`이나 `send_signal(..)`을 보냅니다. 핸들은 파이프도 기다리기도 소유하지 않고, `h.id()`는 자식의 프로세스 id를 주며, 자식이 끝난 뒤에 보낸 시그널은 아무 일도 하지 않습니다.

## TCP와 UDP

`rok::std::net` API는 기본적으로 블로킹입니다. 아래 예제는 서버와 클라이언트를 한 프로그램에서 실행합니다. 포트 `0`에 바인드하면 OS가 빈 포트를 고르고, `local_addr()`가 실제 주소를 알려 줍니다. 서버는 스레드에서 연결 하나를 받아 받은 텍스트를 대문자로 바꿔 돌려보냅니다.

주소로는 `SocketAddr`, `"host:port"` 텍스트(이름은 조회합니다), `(IpAddr, u16)` 쌍, 주소 목록을 쓸 수 있습니다. `TcpStream::connect`, `TcpListener::bind`, `UdpSocket::bind`는 `ToSocketAddrs`를 구현한 무엇이든 받아 주소를 차례로 시도합니다. `net::tcp_connect`, `net::tcp_listen`, `net::udp_bind`는 같은 호출의 자유 함수 판입니다.

소켓 닫기는 실패할 수 있으므로 소켓마다 소유자가 `try s.close()`나 `using`으로 닫습니다. 하나라도 열어 둔 프로그램은 컴파일러가 거부합니다.

```rok
use rok::std::net::{TcpListener, TcpStream, Shutdown};
use rok::core::io::IoError;
use rok::std::thread;

fn main() throws (IoError) {
    let listener = try TcpListener::bind("127.0.0.1:0");
    let addr = try listener.local_addr();

    let server = thread::spawn(|| {
        let (conn, _) = try! listener.accept();
        let msg = try! conn.read_to_str();
        try! conn.write_all(msg.to_uppercase());
        try! conn.close();
        try! listener.close();       // the thread owns the listener now
        msg.len()
    });

    let client = try TcpStream::connect(addr);
    try client.write_all("hello, socket");
    // Half-close: the server's read_to_str sees the end.
    try client.shutdown(Shutdown::Write);
    println(f"reply: {try client.read_to_str()}");
    try client.close();
    println(f"server read {try! server.join()} bytes");
}
```

```output
reply: HELLO, SOCKET
server read 13 bytes
```

한 연결을 두 스레드나 task에서 동시에 읽고 쓰려면 `split()`으로 `ReadHalf`와 `WriteHalf`로 나눕니다. 각 반쪽은 자기 방향을 소유하고, 주인이 닫습니다. 쓰기 반쪽을 닫으면 `shutdown(Shutdown::Write)`처럼 상대에게 스트림이 끝나고, 읽기 반쪽은 그동안 응답을 읽습니다. 두 번째 반쪽을 닫을 때 소켓이 닫힙니다. 어느 반쪽에서든 `shutdown(Shutdown::Both)`를 하면 소켓의 양방향을 닫고, 다른 반쪽에서 막혀 있는 읽기를 깨웁니다. `r.unsplit(w)`는 연결을 되돌려 줍니다. `UnixStream`과 TLS 연결도 같은 방법으로 나눕니다.

```rok
use rok::std::net::{TcpListener, TcpStream, WriteHalf};
use rok::core::io::IoError;
use rok::std::thread;

fn send(w: WriteHalf<TcpStream>) -> i32 {
    try! w.write_all("hello, halves");
    try! w.close();                  // the server's read_to_str sees the end
    0
}

fn main() throws (IoError) {
    let listener = try TcpListener::bind("127.0.0.1:0");
    let addr = try listener.local_addr();
    let server = thread::spawn(|| {
        let (conn, _) = try! listener.accept();
        try! listener.close();
        let msg = try! conn.read_to_str();
        try! conn.write_all(msg.to_uppercase());
        try! conn.close();
        0
    });

    let (r, w) = (try TcpStream::connect(addr)).split();
    let writer = thread::spawn(|| send(w));
    println(f"reply: {try r.read_to_str()}");
    try r.close();                   // the socket closes with the second half
    _ = try! writer.join();
    _ = try! server.join();
}
```

```output
reply: HELLO, HALVES
```

UDP는 연결 없이 데이터그램을 주고받습니다. `recv_from`은 받은 바이트 수와 보낸 쪽의 주소를 반환합니다.

```rok
use rok::std::net;
use rok::core::io::IoError;

fn main() throws (IoError) {
    let a = try net::udp_bind("127.0.0.1:0");
    let b = try net::udp_bind("127.0.0.1:0");
    try b.send_to("ping", try a.local_addr());

    let buf = List::filled(64, 0u8);
    let (n, from) = try a.recv_from(buf);
    println(f"got {n} bytes: {try str::from_utf8(buf[0:n]) catch _ { "?" }}");
    println(f"from b: {from == (try b.local_addr())}");
    try a.close();
    try b.close();
}
```

```output
got 4 bytes: ping
from b: true
```

이 아래에는 OS가 가진 그대로의 소켓인 `net::Socket`이 있습니다. 도메인, 타입, 프로토콜을 직접 고르고, `set_reuse_address`나 `set_only_v6` 같은 옵션을 정한 뒤 `bind` / `listen` / `connect`를 직접 호출합니다. 그다음 `TcpListener::from(s)`(또는 `TcpStream::from`, `UdpSocket::from`)가 소켓을 넘겨받습니다.

```rok
use rok::std::net::{Socket, Domain, SocketType, Protocol, TcpListener};
use rok::core::io::IoError;

fn main() throws (IoError) {
    let s = try Socket::new(Domain::Ipv4, SocketType::Stream, Protocol::TCP);
    try s.set_reuse_address(true);
    try s.bind(try! "127.0.0.1:0".parse());
    try s.listen(16);
    let l = TcpListener::from(s);
    println(f"listening on port 0: {(try l.local_addr()).port() > 0}");
    try l.close();
}
```

```output
listening on port 0: true
```

## 비동기 IO: `*_async`

task 안에서는 블로킹 호출 대신 `_async`가 붙은 같은 이름의 버전을 `await`로 기다립니다([12장](12-concurrency.html) 참고). 소켓을 기다리는 동안에는 task만 멈추고, 스레드는 다른 task를 실행합니다. 일반 파일은 OS가 비동기 대기를 지원하지 않습니다. 그래서 호출은 별도 스레드에서 실행되고 task는 그 결과를 기다립니다. 에러는 동기 버전과 똑같이 던져집니다.

```rok
use rok::std::fs;
use rok::std::fs::File;
use rok::std::net;
use rok::std::net::{TcpStream, Shutdown};
use rok::std::env;
use rok::std::process;

let path = env::temp_dir() / f"rok_learn13_async_{process::id()}.txt";
try! await fs::write_async(path, "written in a task");
let f = try! await File::append_async(path);
try! await f.write_all_async(", then appended");
try! await f.close_async();
println(try! await fs::read_to_str_async(path));
try! await fs::remove_file_async(path);

let l = try! net::tcp_listen("127.0.0.1:0");
let addr = try! l.local_addr();
let server = task::spawn(async {
    let (conn, _) = try! await l.accept_async();
    try! await l.close_async();
    let got = try! await conn.read_to_end_async();
    try! await conn.close_async();
    got.len()
});
let c = try! await TcpStream::connect_async(addr);
try! await c.write_all_async("twelve bytes");
try! await c.shutdown_async(Shutdown::Write);
try! await c.close_async();
println(f"server got {await server} bytes");
```

```output
written in a task, then appended
server got 12 bytes
```

스트림 호출은 io 트레잇에서 옵니다. `AsyncRead`, `AsyncWrite`, `AsyncSeek`, `AsyncClose`가 모든 파일, 소켓, TLS 연결, 자식 pipe에 `read_async`, `write_all_async`, `flush_async`, `seek_async`, `close_async`를 주고, 이 트레잇을 바운드로 받는 여러분의 코드에서도 쓸 수 있습니다. `close_async`는 `close`처럼 값을 닫으므로 닫은 것으로 칩니다. 스트림을 읽고 쓰는 일이 아닌 것만 타입의 메서드입니다. `connect_async`, `accept_async`, `shutdown_async`, 그리고 자식 프로세스의 `Child::wait_async`, `Command::output_async`, `Command::status_async`가 그렇습니다. async 메서드는 자신을 부른 값을 고치므로, 부른 자리에서 바로 `await`합니다([12장](12-concurrency.html)).

연결이 수천 개라면 연결마다 스레드를 두는 것보다 task가 훨씬 가볍습니다. 연결이 몇 개뿐인 도구라면 블로킹 API가 더 간단합니다.

## 정리

- 파일 전체는 `fs::read_to_str` / `fs::write`로, 조금씩은 `File` + `using`으로 다룹니다. 여는 방식에 맞는 함수(`open`, `create`, `create_new`, `open_or_create`, `append`)로 엽니다.
- `Dir` 핸들은 capability입니다. 연 `Dir` 바깥의 것(절대 경로, `..`)은 `PermissionDenied`로 거부됩니다.
- 경로는 `Path`와 `/` 연산자로 만들고, 없을 수 있는 부분은 `T | none`으로 돌아옵니다.
- 바깥 환경을 다룰 때는 `io::stdin/stdout/stderr`, `env::args/var/temp_dir`, `process::Command`를 씁니다.
- TCP / UDP는 `ToSocketAddrs`를 받는 `TcpListener::bind` / `TcpStream::connect` / `UdpSocket::bind`(또는 `net::tcp_listen` / `net::tcp_connect` / `net::udp_bind`)로 엽니다. 옵션을 모두 다루려면 `net::Socket`을 씁니다. 포트 `0`이면 OS가 고릅니다. 소켓은 `try s.close()`나 `using`으로 하나하나 닫습니다.
- task 안에서는 `*_async` 버전을 `await`로 기다립니다. 닫을 때는 `try await s.close_async()`를 씁니다.
- `r.lines()` 같은 어댑터는 `r`의 범위에 머무는 뷰입니다. `r.into_lines()` 같은 `into_` 형태는 reader를 소유하므로 범위를 벗어날 수 있습니다.
